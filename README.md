# The Point — ресторанное QR-меню

Функциональный demo-MVP для показа владельцу ресторана: гость открывает меню по QR конкретного стола, собирает заказ и видит общий чек, кассир получает дополнения без перезагрузки, управляет статусами и стоп-листом, а менеджер следит за базовой аналитикой.

## Что входит

- `/demo` — презентационная страница и быстрый вход в меню тестового стола №7;
- `/menu/[tableToken]` — мобильное меню, модификаторы, сохранённая корзина, отправка заказа и общий live-чек стола;
- `/staff/login` — вход сотрудника через Supabase Auth;
- `/staff/orders` — открываемые чеки по столам, новые дополнения, состав, опции, комментарии и статусы;
- `/staff/menu` — стоп-лист, который сразу обновляет меню гостя;
- `/staff/analytics` — простой CRM-экран с выручкой, количеством и средним чеком, топом блюд и загрузкой по времени;
- `/staff/qr` — наглядный генератор QR-кодов столов с копированием ссылки, PNG и печатью;
- серверная валидация Zod и повторный расчёт цен из базы;
- идемпотентная транзакция создания заказа;
- Supabase PostgreSQL, RLS, Realtime, Auth, миграция и seed;
- автономный demo-режим без внешней базы для быстрой презентации.

В demo-режиме состояние хранится в памяти локального сервера и синхронизируется между телефоном и компьютером коротким polling-запросом. После перезапуска dev-сервера демоданные сбрасываются. Production-режим использует Supabase как единственный источник данных.

## Локальный запуск

Требования: Node.js 20.9+ и npm.

```bash
cp .env.example .env.local
npm install
npm run dev
```

Откройте `http://localhost:3000/demo`. По умолчанию `.env.example` включает автономный demo-режим.

При локальном запуске QR автоматически использует LAN-адрес компьютера вместо `localhost`, поэтому его можно сканировать телефоном в той же Wi‑Fi сети. `npm run dev` уже запускает сервер с доступом к локальной сети.

На странице `/staff/qr` изменение токена автоматически перепривязывает выбранный стол. QR и кнопка проверки активируются после сохранения; старый токен после этого перестаёт работать.

Демо-вход кассира:

- почта: `demo@thepoint.local`
- пароль: `demo123`

## Подключение Supabase

1. Создайте бесплатный проект в Supabase.
2. Установите Supabase CLI или используйте SQL Editor в панели проекта.
3. Примените все миграции из `supabase/migrations` по порядку.
4. Загрузите `supabase/seed.sql`.
5. В `.env.local` заполните:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY
NEXT_PUBLIC_DEMO_MODE=false
```

С Supabase CLI из корня связанного проекта:

```bash
supabase db push
supabase db reset
```

`db reset` применит миграции и `supabase/seed.sql`. Для уже заполненной production-базы используйте `db push`, а seed запускайте только осознанно.

### Создание сотрудника

1. В Supabase откройте Authentication → Users → Add user.
2. Создайте пользователя с рабочей почтой и паролем.
3. Скопируйте его UUID и выполните в SQL Editor:

```sql
insert into public.staff_profiles (user_id, display_name, role)
values ('USER_UUID', 'Кассир', 'cashier');
```

Только пользователи из `staff_profiles` получают доступ к заказам и стоп-листу. Клиентские страницы отправляют access token, а сервер дополнительно проверяет пользователя и профиль сотрудника.

## Переменные окружения

| Переменная | Где используется | Секрет |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | браузер и сервер | нет |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | браузер | нет |
| `SUPABASE_SERVICE_ROLE_KEY` | только серверные API | да |
| `NEXT_PUBLIC_DEMO_MODE` | переключение автономного демо | нет |

Никогда не добавляйте `NEXT_PUBLIC_` к service role key и не коммитьте `.env.local`.

## Размещение на Vercel

1. Импортируйте репозиторий как Next.js-проект.
2. Добавьте четыре переменные окружения из таблицы выше.
3. Для production установите `NEXT_PUBLIC_DEMO_MODE=false`.
4. Выполните Deploy. Команда сборки — `npm run build`, output определяется Next.js автоматически.
5. После получения домена откройте `/staff/qr` и сформируйте QR для каждого стола на URL вида `https://menu.example.ru/menu/TABLE_TOKEN`.

Для смены домена не требуется менять данные в базе: QR содержит обычную ссылку, а уникальный токен стола уже хранится в `tables`.

## Брендинг и меню

Все настройки бренда собраны в `config/restaurant.ts`: название, описание, обложка, контакты, локаль, валюта и палитра. Денежные значения хранятся в минимальных единицах валюты — для рублей это копейки.

Демо-меню для автономного режима находится в `lib/demo-data.ts`. Production-меню загружается из Supabase. Его можно менять SQL-командами или через Table Editor. Фотографии в seed — демонстрационные изображения Unsplash; перед запуском ресторана замените их на собственную съёмку и обновите `image_url`.

### Добавление реального стола и QR

Сгенерируйте непредсказуемый токен, например UUID, и добавьте стол:

```sql
insert into public.tables (table_number, token)
values (11, gen_random_uuid()::text)
returning table_number, token;
```

Сформируйте QR на `https://YOUR_DOMAIN/menu/RETURNED_TOKEN`. Не используйте простой номер стола как токен. Гость не может выбрать или поменять стол в интерфейсе.

## Безопасность заказа

- table token проверяется только сервером;
- клиент не отправляет цены — сервер получает актуальные блюда и модификаторы из базы;
- SQL-функция повторно проверяет наличие, обязательные группы и итог внутри транзакции;
- названия и цены копируются в `order_items` и `order_item_modifiers`;
- `idempotency_key` уникален и защищает от двойной отправки;
- анонимному пользователю закрыт прямой `SELECT` к `tables` и `orders`;
- статус посетителя доступен по отдельному случайному `visitor_token`;
- действия кассира требуют Supabase Auth и записи в `staff_profiles`.
